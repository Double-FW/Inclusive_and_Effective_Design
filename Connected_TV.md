# Accessibility and Usability Guidance for Television and Connected TV Platforms

## Analytical summary

This document is a product-level usability and accessibility guidance framework for television receivers and connected TV platforms (including smart TVs, set‑top boxes and recorders).

It focuses on how people:

- install devices
- configure services
- control hardware
- navigate interfaces
- discover and play content
- use access services and spoken interfaces

The guidance is structured around two complementary areas:

- usability of devices and interfaces
- accessibility features and access services

### What the document is fundamentally about

Modern TV and connected TV products have become increasingly complex. That complexity disproportionately excludes older and disabled users.

The guidance therefore concentrates on:

- first-time setup and configuration
- everyday interaction
- physical controls
- on-screen user interfaces
- access services
- spoken and text-to-speech interfaces

### Core conceptual themes

#### 1. Complexity as the primary accessibility barrier

Connected and hybrid TV platforms introduce:

- network configuration
- accounts and authentication
- multiple content sources
- multiple media players
- fragmented interaction models

Complexity itself is treated as an accessibility failure.

#### 2. Consistency between live and on‑demand services

Accessibility breaks when:

- controls behave differently in different players
- access services are activated in different ways
- availability indicators differ between services

Consistency between live and on‑demand experiences is essential.

#### 3. Hardware and physical interaction

Accessibility includes:

- button layout and grouping
- tactile identification
- spacing
- texture and grip
- physical feedback
- weight and balance

The remote control is a core accessibility interface.

#### 4. Setup and configuration as high‑risk points

Users are most likely to fail during setup because of:

- technical language
- lack of feedback
- inaccessible text entry
- inaccessible network configuration

#### 5. Access services as core features

Subtitles, audio description and signing must support:

- discoverability
- clear indication of availability
- consistent control
- persistence of preferences
- searching and filtering
- recording accessible content

#### 6. Spoken and text‑to‑speech interfaces

Spoken interfaces must provide functional equivalence. Users relying on speech must be able to:

- navigate menus
- browse guides
- discover content
- understand context
- operate device functions

#### 7. Documentation and packaging

Accessibility includes:

- packaging
- quick‑start guides
- full user guides
- alternative formats
- troubleshooting content

#### 8. Testing with disabled users

Interfaces and spoken output must be tested with blind and partially sighted users before release.

## Practitioner‑friendly version

### What this guidance is for

This guidance helps teams build TV and connected‑TV products that real people can use, including:

- older users
- disabled users
- people who rely on subtitles, audio description or spoken output
- people who struggle with complex setup and navigation

It focuses on devices and platforms, not programmes.

### The practical message

Most real accessibility failures come from:

- confusing setup
- inconsistent behaviour between apps and players
- poor remote control design
- inaccessible text entry
- hidden access features

### Design for the hardest moments

Design well for:

- first power‑on
- connecting to the internet
- signing in or creating accounts
- finding something to watch
- turning subtitles or audio description on
- switching between live TV and apps

### Make live TV and apps behave the same

Users should not need to relearn how to:

- turn subtitles on
- enable audio description
- search
- navigate
- play and pause

### Treat the remote control as an accessibility device

The remote control is:

- the main input device
- a tactile interface
- a navigation tool
- a cognitive support tool

### Make setup understandable without a manual

During setup:

- avoid technical language
- show clear progress
- explain what is happening
- make text entry accessible
- provide spoken feedback where possible

### Make access services easy to find

People must be able to:

- see whether content has access services
- search for accessible content
- keep preferences across restarts
- record accessible content

### Make spoken output complete

Spoken output must cover:

- menus and lists
- programme guides
- warnings and prompts
- settings
- playback and recording controls

### Do not forget guides and packaging

Accessibility starts before the screen turns on:

- clear packaging
- accessible quick‑start guides
- plain language manuals
- alternative formats
- realistic troubleshooting

### Test with disabled users

Test real tasks with users who:

- rely on spoken output
- have low vision
- have dexterity impairments
